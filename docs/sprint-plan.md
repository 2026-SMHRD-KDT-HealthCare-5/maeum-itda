## 재조사 결과 (2026-08-13 기준 실제 구현 상태)

**프론트엔드**

- 디자인 적용: Codex 트랙에서 별도 진행 중, 보호자 화면 몇 개만 남고 거의 끝난 상태. 이 작업은 이 일정표의 관리 대상이 아님(Claude→Codex 인수인계 트랙).
- `entities/conversation`, `SeniorDailyRecordPage.tsx`의 옛 계약(`ConversationTurn`/`VoiceCapturedEvent`) 마이그레이션: **완료**. 코드베이스 전체에 옛 타입 참조 없음.
- 시니어 대화 화면(`ChatSocket`, `record-voice-answer`): 실제 `/ws/chats` 연동 코드 완료(Mock 아님) — 원래 Day 3~5 목표를 이미 달성. 단, 로그인이 막혀 있어 브라우저 E2E 확인 불가(아래 참고).
- 보호자 일간 리포트 화면: 디자인 반영 + 데이터 연동 상당 부분 진행됨(최근 커밋 반영).
- PWA 셸(manifest + service worker): **미착수**. 웹 푸시 구독 등록 플로우도 미착수.
- 로그인: `mockResolveRole()`로 역할만 흉내내는 상태 유지 — 아래 백엔드 사유로 계속 블록.

**백엔드(NestJS)**

- `auth`: `check-login-id`, `signup`만 구현되어 있고 **실제 로그인(sign-in) 엔드포인트가 없음**. JWT 발급 로직(`verifyAccessToken`)은 있지만 발급 자체를 트리거하는 라우트가 없어 프론트가 토큰을 받을 방법이 아직 없음.
- `chats`(WS): `ws-protocol.md`의 모든 이벤트와 `GET /chats/messages`까지 NestJS 단독 기준 완료. `packages/shared-types`와도 드리프트 없음.
- `analysis`: 오디오 분석 상태 조회·재시도 엔드포인트와 `AiClient`(FastAPI 호출부) 구현 완료.
- `users`: 서비스 로직(TypeORM 연동)은 있으나 컨트롤러에 라우트가 하나도 없음(내부 호출용으로만 쓰임).
- `reports`, `notifications`: 엔티티만 정의되고 컨트롤러/서비스는 빈 껍데기.
- 웹 푸시(PushSubscription 저장, VAPID, 실제 발송): **코드 전혀 없음**.

**AI 서버(FastAPI)** — "초기 세팅만"이라는 전제가 틀렸음, 실제로는 상당히 진행됐지만 **엉뚱한 프로토콜로 진행됨**:

- STT(OpenAI 우선 + faster-whisper 폴백), 꼬리질문 생성(OpenAI), TTS(Typecast 스트리밍): 실제 구현 완료.
- 감성분석: 텍스트/음성 추론 함수는 있으나 모델 로딩부가 TODO 스텁, 융합(fusion)도 임시 가중평균 가정 로직.
- SGDS-K/GAD-7/LSNS-6 척도채점: **코드 없음.** LLM 프롬프트에 문항 유도용으로만 언급, 실제 채점 로직 자체가 존재하지 않음.
- **치명적 불일치**: 백엔드 `AiClient`는 `POST /analysis/audio/batch`(REST, multipart 배치)를 호출하도록 짜여 있는데, AI 서버는 이 엔드포인트를 아예 구현하지 않고 `/ws/counsel/{session_id}`라는 자체 WebSocket 세션 프로토콜(`session_init`/`utterance_start`/`turn_result`/`tts_chunk_meta`/`tts_end`)을 구현함. Day 0에서 합의했어야 할 BE↔AI 계약이 실제로는 서로 다른 두 프로토콜로 갈라진 채 진행된 것.

## 신규 리스크 (원래 계획에 없던 블로커, 우선 해결 필요)

1. **로그인 API 부재** — 프론트의 모든 실연동(WS `auth` 이벤트 포함)이 여기서 막힘. `POST /auth/login` 구현이 다른 무엇보다 먼저 필요.
2. **AI서버↔백엔드 프로토콜 불일치** — REST 배치냐 WS 세션이냐 팀이 다시 정해야 함. 그대로 두면 8/18(재조정된 통합 체크포인트)에 연결 자체가 안 됨.
3. **척도채점(SGDS-K/GAD-7/LSNS-6) 0% 구현** — 제품 핵심 가치(TextScore 산출)인데 코드가 전혀 없음. 원래 Week2 중반 일정이었지만 AI서버 인력이 프로토콜 재작업에 묶이면 더 밀릴 위험.
4. **웹 푸시 인프라 전무** — 백엔드 구독 저장 API가 없으니 프론트 SW 구독 플로우도 나란히 멈춰 있음. 필수 범위 확정 항목이라 스코프 컷 대상이 아니므로 착수 순서를 앞당겨야 함.

## 스코프 컷 우선순위 (밀리면 이 순서로 버리기)

**실시간 웹 푸시 알림은 필수 범위로 확정 — 컷 대상 아님.** 아래 세 블로커(로그인 API, AI서버 프로토콜, 척도채점)도 기능이 아니라 골든패스 자체를 막는 선행 조건이라 컷 대상이 아니다 — 이게 8/18까지 안 풀리면 스코프를 줄이는 게 아니라 일정 자체를 다시 재협상해야 한다. 정말 밀렸을 때 버릴 순서:

1. 티어 2 화면(회원가입, 연결 화면 2개, 알림함, 주간 리포트) → 시드 계정/고정 데이터로 데모 우회
2. 3개 척도 전부 → 8/20까지도 안 되면 GAD-7 하나만이라도 완결, 나머지는 임시값 유지
3. 티어 3 화면은 이미 실장돼 있어 원래처럼 "먼저 버릴 대상"이 아님 — 버릴 게 있다면 남은 잔여 버그 수정만 스킵

## 작업 방식

- 매일 15분 스탠드업 (비동기도 가능)
- Day 5(8/18)가 사실상의 스프린트 리뷰 — 여기서 스코프 재협상
- AI서버 담당이 가장 리스크 큰 자리(3개 벤더 통합 + 프롬프트 엔지니어링 + 이번에 새로 드러난 프로토콜 재작업까지 겹침) — 막히면 BE 담당이 페어링
- **BE↔AI 프로토콜은 다시 합의하는 즉시 `docs/ws-protocol.md`(또는 별도 REST 계약 문서)에 문서화** — 이번처럼 말로만 합의하고 각자 다르게 구현하는 상황 재발 방지

## Claude → Codex 작업 인수인계 규칙

프론트 화면은 Claude가 1차 구현 후 Codex로 디자인을 보완하는 흐름을 씁니다.

- **스타일 위치**: 시각적 값(색상/spacing/폰트 크기)은 tsx에 인라인으로 넣지 않고 해당 컴포넌트의 `.module.css`에 둔다 (기존 코드베이스 컨벤션 유지)
- **마크업**: Figma 스펙 반영에 필요한 만큼만 — 새 wrapper 컴포넌트를 미리 만들지 않는다
- **클래스명**: 의미 기반 네이밍(`.scoreBadge`, `.avatarWrapper` 등)으로, Codex가 요소를 정확히 찾아 수정할 수 있게 한다
- **인수인계 노트** (PR 설명에 포함, 별도 문서 만들지 않음):
  - 이번에 건드린 파일 목록 (tsx + module.css)
  - 참고한 Figma 레퍼런스 경로(`docs/screens/.../screen-*.png`)와 반영 못 한 `states/` 케이스
  - **스코프 가드**: "이 파일들의 로직(WS 핸들러, API 호출, 상태관리)은 건드리지 말고 className/마크업/CSS 값만 수정" 명시
- Codex 작업 완료 후 `git diff`로 `.module.css`/마크업 외 로직 파일이 바뀌었는지 확인
- BE/AI서버의 핵심 로직(채점 알고리즘, 인증, WS 이벤트 처리)은 Claude 구현 후 Codex에게 검증(버그/보안) 요청하는 용도로 사용 — 디자인 보완과는 별개 트랙

## 날짜별 실행 프롬프트

팀원 각자 자기 Claude Code 세션에 그대로 입력하면 되는 프롬프트입니다. 이 저장소를 열어둔 상태에서 입력하면 `docs/sprint-plan.md`, `docs/ws-protocol.md`, `docs/screens`, `packages/shared-types`를 참고해서 작업합니다.

### Day 0 (완료, 기록용)

- **전원**: "오늘은 Day 0 킥오프야. `docs/ws-protocol.md`를 기준으로 FE↔NestJS, NestJS↔FastAPI 계약(이벤트 필드, DTO, 타임아웃 등)을 확정하고, `packages/shared-types`를 이 문서 기준으로 재정비해줘. 옛 타입(`ConversationTurn`, `VoiceCapturedEvent` 등)을 참조하는 프론트 파일도 찾아서 마이그레이션 대상으로 목록화해줘."
- 실제 결과: FE↔NestJS 계약은 잘 맞았으나, **NestJS↔FastAPI 계약은 합의대로 구현되지 않았음**(AI서버가 REST 배치 대신 자체 WS 세션 프로토콜을 구현) — 2026-08-13 재조사에서 발견, 위 "신규 리스크" 참고.

### Day 1 (완료 vs 미완료 섞임, 기록용)

- **FE/PM/UX**: "오늘은 PWA 셸(manifest+SW) + 로그인 화면 디자인 적용 및 연동을 할 거야. ..." — 실제로는 로그인 화면 디자인은 Codex 트랙으로 넘어갔고, 연동은 백엔드 로그인 API 부재로 막혔음. PWA 셸도 착수되지 않음 — 둘 다 Day 2로 이연.
- **BE/DB (8/12)**: "현재 구현된 WS 이벤트, `packages/shared-types`, `docs/ws-protocol.md`를 비교해 이름과 payload 불일치를 정리해줘. ..." — 이 부분은 완료됐고 드리프트 해소됨(2026-08-13 재조사 확인).
- **AI서버**: "오늘은 Day 0 계약 확정에 참여하고, faster-whisper STT 엔드포인트를 구현할 거야. ..." — STT는 실제로 완성됐으나, 이때 BE↔AI REST 계약 대신 자체 WS 프로토콜 방향으로 진행된 것으로 추정됨.

### Day 2 (오늘, 8/13)

- **BE/DB**: "오늘은 두 가지가 최우선이야. 1) `apps/backend/src/auth`에 실제 로그인(sign-in) 엔드포인트(`POST /auth/login`)를 구현해줘 — 아이디/비밀번호 검증 후 JWT 발급까지. 기존 `check-login-id`/`signup`과 같은 컨벤션으로. 2) AI서버 팀원과 함께 `apps/ai-server`의 실제 프로토콜(`/ws/counsel/{session_id}`)과 `apps/backend/src/analysis/ai.client.ts`가 기대하는 `POST /analysis/audio/batch` REST 배치 계약이 서로 다르다는 걸 확인하고, 어느 쪽으로 통일할지 정리해줘."
- **FE/PM/UX**: "오늘은 PWA 셸(manifest + service worker)을 구현할 거야. 백엔드 의존 없는 작업이니 로그인 API를 기다리지 않고 바로 진행해줘. 설치 가능한 PWA 최소 조건(manifest.json, 기본 SW 등록)까지."
- **AI서버**: "오늘은 백엔드 팀원과 함께 AI서버 프로토콜(`/ws/counsel/{session_id}`)과 백엔드가 기대하는 REST 배치 계약(`POST /analysis/audio/batch`)의 불일치를 확인하고 통일 방향을 정할 거야. 그 후 SGDS-K/GAD-7/LSNS-6 중 GAD-7 채점 로직부터 설계 착수해줘(지금 척도채점 코드가 전혀 없는 상태야)."

### Day 3 (8/14)

- **FE/PM/UX**: "로그인 API가 준비됐으면 `mockResolveRole()`을 제거하고 실제 로그인 연동으로 교체해줘. 성공하면 그 즉시 시니어 대화 화면에서 실제 브라우저로 로그인→WS 인증→대화 1턴까지 확인해줘(WS 클라이언트 코드는 이미 구현돼 있어)."
- **BE/DB**: "로그인 엔드포인트가 프론트와 잘 붙는지 확인해주고, 이제 웹 푸시 인프라를 시작할 거야. `PushSubscription` 저장용 엔티티와 구독 등록 REST 엔드포인트, VAPID 키 발급을 구현해줘."
- **AI서버**: "어제 합의한 프로토콜 방향으로 백엔드와의 연동을 재작업해줘. 그리고 감성분석 모델 로딩부(현재 TODO 스텁)를 실제 모델 연결로 바꿔줘."
