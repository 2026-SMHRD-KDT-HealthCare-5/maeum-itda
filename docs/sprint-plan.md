- **문항 커버리지/여러 날치 대화 컨텍스트가 시스템 어디에도 전달 안 됨** — AI서버 `SessionState.pending_scale_items`/`prev_session_summary` 필드는 있지만 백엔드가 채워 보내는 코드가 없음(무상태 구조)

- **TTS는 AI서버만 완료** — 백엔드 계약(`audio-analysis.contract.ts`)에 필드 없음, `tts:audio` WS 이벤트 없음, 프론트 재생 컴포넌트 없음. `docs/ws-protocol.md` §8도 "MVP 이후"로 stale 표기 중
- **TTS 재생·마이크 녹음 순서가 정해진 적 없음** — `useRecordVoiceAnswer`가 질문 도착 즉시 마이크를 여는데 TTS 재생과 겹치면 에코 위험
- **모바일(iOS) 자동재생 정책 리스크** — `AudioContext`가 `suspended` 상태로 시작해 묵음 감지가 조용히 깨질 수 있고, TTS `.play()`도 사용자 제스처 없이 막힐 수 있음(오디오 포맷 자체는 webm→mp4 폴백+서버 매핑까지 이미 안전)
- 프론트 `GuardianHomePage.tsx`에 "다솔" 오타(다슬 아님) — 사소하지만 미반영
- **`apps/ai-server/.env` 자체가 없어 실제 API 키가 전무** — `OPENAI_API_KEY`/`TYPECAST_API_KEY`/`TYPECAST_VOICE_ID` 전부 미설정. **팀원이 갖고 있고 8/18에 전달받기로 확정** — 그 전까지 실제 API 호출 검증(척도 채점 품질, TTS 실제 재생)은 전부 8/18로 이월, 8/15~17은 코드 작성까지만

## 작업 방식

- 매일 15분 스탠드업(비동기 가능)
- 8/20이 사실상의 스프린트 리뷰이자 최종 체크포인트 — 8/21 이후 불확실하므로 여기서 반드시 데모 가능한 최소 상태를 확정
- AI서버 담당이 가장 리스크 큰 자리(벤더 통합+프롬프트 엔지니어링) — 막히면 BE 담당이 페어링
- **BE↔AI 프로토콜은 다시 합의하는 즉시 `docs/ws-protocol.md`(또는 별도 REST 계약 문서)에 문서화** — 말로만 합의하고 각자 다르게 구현하는 상황 재발 방지
- 특정 항목이 늦어질 조짐이 보이면 조용히 빼지 말고 그날 스탠드업에서 바로 공유해서 인력 재배치

## Claude → Codex 작업 인수인계 규칙

프론트 화면은 Claude가 1차 구현 후 Codex로 디자인을 보완하는 흐름을 씁니다.

- **스타일 위치**: 시각적 값(색상/spacing/폰트 크기)은 tsx에 인라인으로 넣지 않고 해당 컴포넌트의 `.module.css`에 둔다 (기존 코드베이스 컨벤션 유지)
- **마크업**: Figma 스펙 반영에 필요한 만큼만 — 새 wrapper 컴포넌트를 미리 만들지 않는다
- **클래스명**: 의미 기반 네이밍(`.scoreBadge`, `.avatarWrapper` 등)으로, Codex가 요소를 정확히 찾아 수정할 수 있게 한다
- **인수인계 노트** (PR 설명에 포함, 별도 문서 만들지 않음):
  - 이번에 건드린 파일 목록 (tsx + module.css)
  - 참고한 Figma 레퍼런스 경로(`docs/screens/.../screen-*.png`)와 반영 못 한 `states/` 케이스
  - **스코프 가드**: "이 파일들의 로직(WS 핸들러, API 호출, 상태관리)은 건드리지 말고 className/마크업/CSS 값만 수정" 명시
- Codex 작업 완료 후 `git diff`로 `.module.css`/마크업 외 로직 파일이 바뀌었는지 확인
- BE/AI서버의 핵심 로직(채점 알고리즘, 인증, WS 이벤트 처리)은 Claude 구현 후 Codex에게 검증(버그/보안) 요청하는 용도로 사용 — 디자인 보완과는 별개 트랙
