## 현재 상태 (2026-08-19): 기능 구현·배포 배선 완료, ai-server 배포만 대기

12개 화면 전부 실 API/WS 연동 완료(아래 화면 우선순위 표 참고). 안부 대화 파이프라인(STT→감정분석→척도채점→꼬리질문→TTS)은 실모드(`model`)로 end-to-end 스모크 테스트까지 마쳤다. 프론트(Vercel)·백엔드(Render) 배포 환경변수(`VITE_API_BASE_URL`/`VITE_WS_BASE_URL`, `CORS_ORIGINS`, `AI_BASE_URL`)도 전부 등록 완료. **유일하게 남은 배선은 ai-server(FastAPI) 자체의 Render 배포** — 진행 중이며, 배포되는 즉시 아래 "ai-server 배포 완료 후 확인할 것"만 확인하면 된다.

## 남은 작업 (8/21까지)

### ai-server 배포 완료 후 확인할 것 (우선순위 1)

1. **ai-server 환경변수** — `OPENAI_API_KEY`/`TYPECAST_API_KEY`/`TYPECAST_VOICE_ID`와 `SCALE_ANALYSIS_MODE`/`STT_CORRECTION_MODE`/`DAILY_SUMMARY_MODE`/`EMOTION_MODE` 4개 전부 `model`인지 확인(로컬 `.env`는 gitignore라 Render 환경변수는 별도로 채워야 함).
2. **감정모델 체크포인트 포함 여부** — 체크포인트 파일이 Git ignore 대상이라, Render가 git clone만으로 빌드한다면 배포 이미지에 파일 자체가 없을 수 있다. Docker 이미지 포함/별도 다운로드 스텝/Git LFS 중 무엇을 쓰는지 확인.
3. **Kresnik 음성 감정모델의 huggingface.co 네트워크 의존성** — 최초 로딩 시 실제 네트워크 요청을 보낸다(체크포인트가 로컬에 있어도). Render 인스턴스가 그 접근이 되는지, 안 되면 `HF_HUB_OFFLINE=1`(서버 프로세스 셸에 직접 설정) + 캐시 사전 포함으로 우회할 것.
4. **데모 시작 전 워밍업 호출 1회** — 감정 모델은 프로세스 내 최초 1회만 로딩되고 이후엔 메모리에 남아 빠르다(`@lru_cache`). 라이브 중 첫 답변에서 로딩 지연이 노출되지 않도록 더미 답변으로 미리 한 번 호출해둘 것.

### ai-server 배포 완료 즉시 (우선순위 2)

5. **실제 배포 도메인 기준 골든패스 전체 리허설** — 로그인→WS인증→마이크 답변→STT/TTS→척도채점→질문생성→리포트 갱신(일간요약 포함)→위험 알림 시 웹 푸시 수신까지, **노트북과 모바일(PWA 설치) 둘 다**로 완주 확인. 로컬에서 되던 것과 배포 환경이 실제로 다르게 동작한 전례가 있었으니(프론트 env var 미설정 건), 반드시 배포 도메인 기준으로 재확인할 것.
6. **Render 백엔드 콜드스타트 대비** — 무료 티어는 유휴 시 스핀다운되며, 재시작 시 `ChatConnectionStateService`의 인메모리 세션 상태가 초기화돼 재진입 시 대화가 새로 시작된다. DB 기준으로 오늘 대화를 이어가도록 하는 수정을 한 차례 시도했으나(`fix/resume-todays-conversation`) 되돌렸다 — **백엔드 담당이 직접 다시 구현하기로 함**. 그 전까지는 데모 시작 직전 워밍업 핑으로 콜드스타트 자체가 라이브 중 발생하지 않게 하는 것으로 대응.

### 낮은 우선순위 (영향 없음, 시간 남으면)

7. `SCALE_QUESTION_ANALYSIS` 테이블에 스펙 문서(`테이블명세서_마음잇다.pdf`)엔 있는 `IS_MATCHED` 컬럼이 실제 엔티티/스키마엔 없음 — TextScore 계산엔 영향 없어서 보류.

## 완료됨

- **프론트**: 로그인/회원가입(localStorage 세션), 시니어·보호자 연결 요청·수락·거절·해제, 시니어 대화 화면(WS 실연동, STT 실시간 반영, TTS 재생), 보호자 대시보드/알림함/일간·주간 리포트, 시니어 이전 대화 기록, 내 정보, 출석 캘린더, 웹 푸시 구독 등록 — 전부 실 API 연동. 배포(Vercel) 환경변수 등록 완료.
- **백엔드**: 로그인, WS 인증·대화·음성 수신, 문항 커버리지/이전 세션 요약/최근 대화 5턴 조회, TTS 중계, 정서지수 즉시 재계산 트리거, 일간 요약 저장, 웹 푸시 발송 인프라(VAPID·구독 저장·임계치 발송) — 전부 구현 완료. 배포(Render) 환경변수 등록 완료.
- **AI서버**: STT(OpenAI 우선+whisper 폴백), STT 교정, 척도 채점(SGDS-K/GAD-7/LSNS-6), 꼬리질문 생성, TTS(Typecast), 일간 요약·추천행동 생성 — 전부 구현 완료, 실모드 스모크 테스트로 검증됨. **Render 배포만 진행 중(D-2 유일한 블로커).**
- **5감정 모델**: KLUE 텍스트·Kresnik 음성 모델 연동 완료. 보정·가중합 파라미터는 최종 테스트 세트 평가 전 후보값.

## 의도적으로 미룸 (데모 전 손대지 않음)

- 다중 기기(탭) 동시 접속 시 질문/답변 상태 충돌 — 데모는 단일 기기 진행이라 위험 낮음.
- UC-04 감성분석 아키텍처를 요구사항정의서 스펙(질문생성 LLM과 같은 구조화 출력)에 맞추는 재설계 — 현재 구현(KLUE/Kresnik 별도 분류 → LLM 입력)도 기능은 정상 동작.
- UC-06-3 "acoustic feature(톤/피치) 추출" 문구를 실제 구현(엔드투엔드 음성 감정분류 모델)에 맞게 문서화.
- UC-02 무응답 재촉진 타이밍 스펙 일치화 — 스펙은 "10초 무응답 시 AI가 동적 재촉진 질문 생성"이지만 실제는 30초 고정 안내 후 10분 무응답 시 종료. "AI 동적 재질문 생성" 부분만 스펙과 다르게 남음.
- STT/TTS 외부 API 재시도 로직 추가 — STT는 이미 OpenAI 실패 시 로컬 whisper 폴백 있음.
- 코드 품질 리팩터링 전반(`useRecordVoiceAnswer` 복잡도, `SttStatus` 죽은 상태값, `session_manager.py` 죽은 코드, 프론트 `wsClient.ts` 타입 중복 등) — 기능엔 영향 없음.
- 척도 문항(SGDS-K/GAD-7/LSNS-6) 공식 번역 대조, 테스트 커버리지 보강 전반.
- STT 원문 먼저 보여주고 LLM 교정 시 교체하는 2단계 스트리밍(질문→답변 체감 지연 개선안) — 비용 대비 효과 낮다고 판단, 상태표시(답변 대기중/듣는중 구분)로 체감 지연 문제는 대부분 해결됨.

## 작업 방식

- 매일 스탠드업(비동기 가능)에서 "남은 작업" 목록 기준으로 진행 상황 공유
- **BE↔AI 프로토콜은 합의하는 즉시 `docs/ws-protocol.md`(또는 별도 REST 계약 문서)에 문서화** — 말로만 합의하고 각자 다르게 구현하는 상황 재발 방지
- 특정 항목이 늦어질 조짐이 보이면 조용히 빼지 말고 스탠드업에서 바로 공유해서 인력 재배치

## Claude → Codex 작업 인수인계 규칙

프론트 화면은 Claude가 1차 구현 후 Codex로 디자인을 보완하는 흐름을 씁니다.

- **스타일 위치**: 시각적 값(색상/spacing/폰트 크기)은 tsx에 인라인으로 넣지 않고 해당 컴포넌트의 `.module.css`에 둔다
- **마크업**: Figma 스펙 반영에 필요한 만큼만 — 새 wrapper 컴포넌트를 미리 만들지 않는다
- **클래스명**: 의미 기반 네이밍(`.scoreBadge`, `.avatarWrapper` 등)으로, Codex가 요소를 정확히 찾아 수정할 수 있게 한다
- **인수인계 노트** (PR 설명에 포함, 별도 문서 만들지 않음): 이번에 건드린 파일 목록, 참고한 Figma 레퍼런스 경로와 반영 못 한 `states/` 케이스, **스코프 가드**("이 파일들의 로직은 건드리지 말고 className/마크업/CSS 값만 수정")
- Codex 작업 완료 후 `git diff`로 `.module.css`/마크업 외 로직 파일이 바뀌었는지 확인
- BE/AI서버의 핵심 로직(채점 알고리즘, 인증, WS 이벤트 처리)은 Claude 구현 후 Codex에게 검증(버그/보안) 요청하는 용도로 사용 — 디자인 보완과는 별개 트랙
