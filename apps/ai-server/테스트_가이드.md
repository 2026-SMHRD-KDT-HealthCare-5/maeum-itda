# 마음잇다 AI 서버 — REST/모듈 테스트 가이드

이 문서는 실제 백엔드 없이 AI 서버의 개별 기능과 REST 전체 흐름을 검증하는 방법을
정리합니다. 모든 명령은 `apps/ai-server`를 현재 디렉터리로 두고 실행합니다.

## 테스트 구성

| 구분 | 대상 | 서버 실행 | 실행 파일 |
| --- | --- | --- | --- |
| STT 개별 테스트 | `app/services/stt.py` | 불필요 | `scripts/test_stt.py` |
| LLM 개별 테스트(감정 판단 포함) | `app/services/llm.py` | 불필요 | `scripts/test_llm.py` |
| TTS 개별 테스트 | `app/services/tts.py` | 불필요 | `scripts/test_tts.py` |
| REST 전체 테스트 | STT → LLM(감정·척도·꼬리질문) → TTS | 필요 | `scripts/mock_backend_client.py` |

개별 테스트 스크립트는 실제 서버가 사용하는 `app/services/*.py`를 직접 import합니다.
테스트용으로 AI 기능을 별도 복제하지 않습니다.

## 0. 사전 준비

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

`.env`에는 사용하는 기능에 맞게 값을 설정합니다.

- `OPENAI_API_KEY`: STT와 LLM(감정 판단·척도 채점·꼬리질문 생성)
- `TYPECAST_API_KEY`, `TYPECAST_VOICE_ID`: TTS 개별 테스트
- `LOCAL_WHISPER_DEVICE=cpu`: CUDA 환경이 없을 때 권장

`.env` 변경 후 실행 중인 서버는 완전히 종료하고 다시 시작합니다.

## 1. 입출력 폴더

```text
input_sound/   STT 및 REST 테스트 오디오
output_text/   STT 결과와 REST 응답 JSON
input_text/    TTS 테스트 입력 텍스트
output_sound/  TTS 개별 테스트 결과
```

이 폴더들은 테스트 스크립트 편의를 위한 것입니다. 실제 REST 서버는 요청으로 받은
오디오를 메모리에서 처리하고 결과를 JSON 응답으로 반환합니다.

## 2. 개별 기능 실행

### STT

```powershell
python scripts/test_stt.py --audio input_sound/sample.webm
python scripts/test_stt.py --audio input_sound/sample.webm --engine openai
python scripts/test_stt.py --audio input_sound/sample.webm --engine local
```

`--engine auto`가 기본값이며 OpenAI 실패 시 로컬 Whisper로 폴백합니다. 결과는 콘솔과
`output_text/{파일명}_{시각}.txt`, `.json`에 저장됩니다.

### LLM (감정 판단 포함)

```powershell
python scripts/test_llm.py `
  --text "요즘 밤에 잠을 잘 못 자요" `
  --voice-features "duration_sec:4.2,rms_energy:0.03,silence_ratio:0.18,pitch_variation_hz:12.4" `
  --prev-summary "지난주에는 무릎이 아프다고 하셨음" `
  --pending "SGDS_K:Q3,Q7;GAD_7:Q2"
```

`SessionState`를 CLI 입력으로 구성해 실제 `generate_next_question()`을 호출합니다.
2026-08-21부터 감정 판단(`sentiment_label`)도 별도 모델이 아니라 이 LLM 호출이
STT 텍스트와 `--voice-features`(생략 시 빈 값)를 함께 참고해 결정합니다. `--voice-features`는
`app/services/audio_features.py`의 `extract_features()`가 반환하는 키(`duration_sec`,
`rms_energy`, `silence_ratio`, `pitch_variation_hz`)와 동일한 이름을 씁니다. 현재 REST
요청에는 이전 요약과 미채점 척도 문항이 없으므로, 이 두 옵션을 사용한 결과는 REST
호출 결과와 다를 수 있습니다.

### TTS

```powershell
python scripts/test_tts.py --text "오늘 하루는 어떻게 보내셨어요?"
python scripts/test_tts.py --text "오늘 하루는 어떻게 보내셨어요?" --stream
python scripts/test_tts.py --list-voices
```

기본 실행은 REST 엔드포인트와 동일한 `synthesize_full()`을 호출합니다. `--stream`은
`synthesize_stream()`을 호출해 첫 청크 도달 시간(TTFB)을 별도로 확인합니다.

## 3. REST 전체 흐름 실행

첫 번째 터미널에서 서버를 실행합니다.

```powershell
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

헬스체크를 먼저 확인할 수 있습니다.

```powershell
Invoke-RestMethod http://localhost:8000/health
```

두 번째 터미널에서 목 백엔드 클라이언트를 실행합니다.

```powershell
python scripts/mock_backend_client.py --audio input_sound/sample.webm
```

복수 음성은 `--audio`를 반복합니다.

```powershell
python scripts/mock_backend_client.py `
  --audio input_sound/answer-1.webm `
  --audio input_sound/answer-2.webm
```

목 클라이언트는 백엔드와 동일한 multipart 필드로 다음 엔드포인트를 호출합니다.

```http
POST /analysis/audio/batch
Content-Type: multipart/form-data
```

처리 순서:

```text
multipart 요청 → 음성별 STT → 음성별 감정분류 → 묶음 전체 LLM 질문 생성
→ 다음 질문 TTS → answers[], nextQuestion, Base64 TTS JSON 응답
```

응답은 `output_text/mock_rest_{시각}.json`에 저장됩니다. 목 클라이언트는
`ttsAudioBase64`를 디코딩하여 `output_sound/mock_rest_tts_{시각}.{포맷}`에도 저장합니다.

## 4. 확인해야 할 응답 형식

```json
{
  "answers": [
    {
      "messageId": 102,
      "transcript": "오늘 산책을 다녀왔어요.",
      "sentimentLabel": "POSITIVE",
      "scaleAnalyses": []
    }
  ],
  "nextQuestion": "산책하면서 무엇이 가장 좋으셨어요?",
  "ttsAudioBase64": "SUQzBAAAAA...",
  "ttsMimeType": "audio/mpeg"
}
```

- 요청과 응답의 `messageId`가 일치해야 합니다.
- `sentimentLabel`은 `POSITIVE`, `NEUTRAL`, `NEGATIVE` 중 하나입니다.
- 척도 식별자는 `SGDS_K`, `GAD_7`, `LSNS_6`를 사용합니다.
- 현재 척도 채점 로직은 연결 전이므로 `scaleAnalyses`는 빈 배열입니다.
- `ttsAudioBase64`를 디코딩한 음성이 비어 있지 않고 재생 가능한지 확인합니다.
- `ttsMimeType`과 저장한 파일 확장자가 일치해야 합니다.

## 5. 자주 겪는 문제

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `No module named 'app'` | 프로젝트 루트가 아닌 곳에서 실행 | `apps/ai-server`에서 명령 실행 |
| multipart 관련 런타임 오류 | `python-multipart` 미설치 | `pip install -r requirements.txt` |
| STT `403 model_not_found` | STT 모델 접근 권한 없음 | 접근 가능한 모델로 `.env` 변경 |
| `cublas64_12.dll` 오류 | CUDA 런타임 없음 | `LOCAL_WHISPER_DEVICE=cpu` 설정 |
| 감정 결과가 균등분포 | 체크포인트 누락 또는 로딩 실패 | 모델 경로와 로딩 코드 확인 |
| Typecast `401` | 키 오류 또는 서버가 이전 환경변수 사용 | 키 확인 후 프로세스 재시작 |
| 백엔드 AI 요청 타임아웃 | 전체 분석이 백엔드 제한을 초과 | 처리 시간 측정 후 AI 경로 최적화 |

## 6. 실제 백엔드 연결 전 확인 목록

- `GET /health` 성공
- 단일·복수 음성 REST 호출 성공
- 응답 `messageId`가 요청과 일치
- STT, 감정, LLM 개별 실행 성공
- TTS 개별 실행과 REST 응답 TTS 파일 저장 성공
- 전체 응답 시간이 백엔드 제한 안에 들어오는지 측정
- 백엔드 환경변수 `AI_BASE_URL`이 AI 서버 주소를 가리키는지 팀에 확인
