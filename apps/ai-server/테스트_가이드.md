# 마음잇다 AI 서버 — 목업/모듈 테스트 가이드

이 문서는 실제 백엔드(Node/Nest.js) 없이, AI 서버(`app/`)의 각 모듈과 전체 WebSocket
흐름을 로컬에서 검증하는 방법을 정리한 것이다.

## 테스트 방식은 두 층으로 나뉜다

| | 대상 | 서버 실행 필요 | 스크립트 |
|---|---|---|---|
| 모듈 단위 테스트 | `app/services/*.py` 하나씩 | 불필요 (함수 직접 호출) | `scripts/test_stt.py`, `test_tts.py`, `test_emotion.py`, `test_llm.py` |
| 전체 파이프라인 테스트 | `app/main.py` (WS 핸들러 전체) | 필요 (uvicorn으로 띄운 상태) | `scripts/mock_backend_client.py` |

모듈 단위 스크립트는 `app/main.py`가 실제로 쓰는 것과 **동일한 서비스 파일**을
그대로 import해서 호출한다 (`from app.services import stt as stt_service` 등).
별도로 복사해둔 코드가 아니므로, 모듈 단위로 검증된 내용은 곧 실제 서버 코드의
동작을 확인한 것과 같다.

## 0. 사전 준비

```powershell
cd "C:\Users\smhrd1\Desktop\프로젝트 통합본\최종 핵심 프로젝트\AI서버"
pip install -r requirements.txt
copy .env.example .env   # 없다면. 있으면 생략
```

`.env`에 아래 값들을 실제 값으로 채워야 각 API 호출이 정상 동작한다.

- `OPENAI_API_KEY` — STT(gpt-4o-transcribe 등) / LLM(gpt-4o) 공용
- `TYPECAST_API_KEY`, `TYPECAST_VOICE_ID` — TTS
- `LOCAL_WHISPER_DEVICE=cpu` — 로컬 whisper 폴백을 CPU로 고정 (GPU 드라이버/CUDA
  라이브러리 이슈 회피용으로 권장. `cublas64_12.dll` 관련 오류가 나면 이 설정 확인)

> **주의**: `.env`를 수정한 뒤에는, 서버가 `uvicorn ... --reload`로 떠 있어도
> **자동으로 반영되지 않는다**. uvicorn의 `--reload`는 기본적으로 `.py` 파일
> 변경만 감지하기 때문. `.env`를 바꿨다면 서버 터미널에서 `Ctrl+C`로 완전히
> 종료 후 다시 실행해야 한다.

윈도우에서 `python` 명령어가 버전 정보 없이 이상하게 동작하거나(마이크로소프트
스토어 스텁 등에 가로채인 경우), `python --version` 결과가 이상하다면 파이썬
전체 경로로 우회한다:

```powershell
& "C:\Users\smhrd1\AppData\Local\Programs\Python\Python312\python.exe" -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## 1. 입출력 폴더 규칙

프로젝트 루트에 아래 4개 폴더가 있고, 테스트 스크립트들은 전부 이 규칙을 따른다.

```
input_sound/    STT 테스트용 오디오를 넣어두는 곳 (test_stt.py, mock_backend_client.py가 여기서 자동 탐색)
output_text/    STT 인식 결과 / turn_result가 저장되는 곳 (.txt+.json 또는 .json)
input_text/     TTS 테스트용 텍스트(.txt)를 넣어두는 곳 (test_tts.py가 여기서 자동 탐색)
output_sound/   TTS로 합성된 오디오가 저장되는 곳 (test_tts.py, mock_backend_client.py)
```

각 폴더 안에 파일이 **정확히 1개**일 때만 자동 선택되고, 0개/2개 이상이면
스크립트가 에러 메시지를 띄우고 종료한다 (`--audio`/`--text`로 직접 지정하면
자동 탐색을 건너뛴다).

**참고**: 이 4개 폴더는 어디까지나 테스트 스크립트 전용 편의 장치다. 실제
서버(`app/services/stt.py`, `app/services/tts.py`)는 이 폴더를 전혀 참조하지
않는다 — WebSocket으로 받은 오디오 바이트/텍스트를 메모리에서 바로 처리하고,
결과도 파일로 저장하지 않고 곧바로 WS로 스트리밍한다.

## 2. 모듈 단위 테스트

서버를 띄우지 않아도 된다. 각각 독립적으로 실행 가능.

### STT

```powershell
cd scripts
python test_stt.py                        # input_sound/ 안 파일 자동 탐색
python test_stt.py --audio my_voice.wav    # 특정 파일 지정
python test_stt.py --engine openai         # OpenAI 경로만 강제
python test_stt.py --engine local          # 로컬 whisper만 강제 (API 키 없어도 됨)
```

결과는 콘솔 출력 + `output_text/{원본파일명}_{시각}.txt`, `.json`로 저장.

### TTS

```powershell
cd scripts
python test_tts.py                            # input_text/ 안 .txt 자동 탐색
python test_tts.py --text "오늘 하루는 어떻게 보내셨어요?"
python test_tts.py --list-voices               # 보유 보이스 목록만 조회
```

TTFB(첫 청크 도달 시간, 요구사항정의서 FR-01-05 목표 ~200ms)를 측정해 출력.
결과는 `output_sound/tts_{시각}.{포맷}`.

### 감정분류

```powershell
cd scripts
python test_emotion.py --text "요즘 잠을 잘 못 자요"
python test_emotion.py --text "..." --audio ../input_sound/my_voice.wav
```

`models/text_emotion/`, `models/voice_emotion/`에 실제 체크포인트가 없으면
균등분포(라벨 5개 기준 0.2씩)가 나오는 게 **정상**이다 (모델 로딩 실패 시
파이프라인이 죽지 않도록 하는 의도된 폴백). 실제 값이 나오게 하려면 학습된
체크포인트를 해당 폴더에 넣고 `app/services/emotion.py`의 `_get_text_model()`/
`_get_voice_model()` 로딩 코드를 실제 모델 형식에 맞게 수정해야 한다.

### LLM

```powershell
cd scripts
python test_llm.py --text "걱정해줘서 고마워" --emotion "happy:0.6,neutral:0.4" \
    --prev-summary "지난주엔 무릎이 아프다고 하셨음" \
    --pending "SGDS_K:Q3,Q7;GAD_7:Q2"
```

`SessionState`를 CLI 인자로 직접 구성해서 `generate_next_question()`을 호출한다.

## 3. 전체 파이프라인 테스트 (mock_backend_client.py)

서버가 떠 있어야 한다. 터미널 하나에서:

```powershell
cd "C:\Users\smhrd1\Desktop\프로젝트 통합본\최종 핵심 프로젝트\AI서버"
& "C:\Users\smhrd1\AppData\Local\Programs\Python\Python312\python.exe" -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

다른 터미널에서:

```powershell
cd "C:\Users\smhrd1\Desktop\프로젝트 통합본\최종 핵심 프로젝트\AI서버\scripts"
& "C:\Users\smhrd1\AppData\Local\Programs\Python\Python312\python.exe" mock_backend_client.py
```

`input_sound/`에 오디오 파일이 하나 있으면 `--audio` 없이 바로 실행된다.

**동작 순서**: `session_init` 전송 → `utterance_start` 전송 → 오디오 바이너리
전송 → 서버가 STT→감정분류→LLM→TTS를 순서대로 처리 → `turn_result`(텍스트/감정/
다음질문) 수신 → TTS 청크(`tts_chunk_meta` + 바이너리)를 여러 번 수신 →
`tts_end` 수신 → `session_end` 전송하고 종료.

**결과 저장**:
- `output_text/mock_{원본파일명}_{시각}.json` — `turn_result` 전체
- `output_sound/mock_tts_{시각}.{포맷}` — TTS 오디오 (`.env`의
  `TYPECAST_AUDIO_FORMAT`을 따름. 기본 mp3)

## 4. 자주 겪은 문제와 원인

| 증상 | 원인 | 해결 |
|---|---|---|
| `ModuleNotFoundError: No module named 'app'` | `app/main.py`를 스크립트 경로로 직접 실행(VS Code ▶ 버튼 등). 이 경우 파이썬이 `app/` 폴더만 sys.path에 넣고 프로젝트 루트는 안 넣음 | 프로젝트 루트에서 `python -m uvicorn app.main:app --reload`로 실행 |
| `python` 실행 시 버전 정보 없이 "Python"만 출력 | `python` 명령어가 실제 인터프리터가 아닌 다른 것(스토어 스텁/별칭)에 가로채임 | 파이썬 전체 경로로 직접 실행 |
| STT `403 model_not_found` | OpenAI 프로젝트가 해당 STT 모델에 대한 접근 권한이 없음(플랫폼 프로젝트 설정) | `gpt-4o-transcribe` 등 접근 가능한 모델로 `.env`의 `OPENAI_STT_MODEL` 변경 |
| 로컬 whisper `cublas64_12.dll is not found` | `LOCAL_WHISPER_DEVICE=auto`가 CUDA를 잡았는데 시스템에 CUDA 런타임이 없음 | `.env`에 `LOCAL_WHISPER_DEVICE=cpu` 설정 |
| `faster_whisper` `No module named` | 패키지 미설치 | `pip install -r requirements.txt` 또는 `pip install faster-whisper` |
| Typecast `401 AUTH_TOKEN_INVALID` (키를 새로 넣었는데도) | uvicorn `--reload`가 `.env` 변경은 감지 못함 → 서버가 예전 값을 계속 사용 | 서버를 `Ctrl+C`로 완전히 종료 후 재시작 |
| `.env` 값이 실행 위치에 따라 안 읽힘 | `env_file`이 상대경로라 cwd 기준으로 찾음 | `app/config.py`에서 `Path(__file__).resolve().parent.parent / ".env"`로 고정(이미 반영됨) |
