CLAUDE.md의 "새 작업 시작 전 브랜치 확인" 규칙과 AGENTS.md의 Git 컨텍스트 확인 규칙을 실행한다.

1. `git branch --show-current`와 `git status --short`를 실행해 현재 브랜치와 워킹트리 상태를 확인한다. 대화 맥락이나 이전 작업의 브랜치 상태를 그대로 믿지 않는다.
2. 워킹트리에 미커밋 변경사항이 있다면, 먼저 그게 누구 것인지 파악한다(이번 세션에서 방금 만든 것인지, 이전 세션·다른 도구·사용자가 남겨둔 것인지). 소유자를 확인하기 전에는 stash/삭제/덮어쓰지 않는다. 사용자 것이거나 출처가 불분명하면 먼저 사용자에게 확인한다.
3. 현재 브랜치가 `dev`가 아니면:
   - 이름이 `feat/기능이름` 컨벤션을 따르는지, 그리고 지금 하려는 작업과 브랜치 범위가 맞는지만 확인해서 짧게 보고한다.
   - 이미 적절한 feature 브랜치 위라면 새로 만들지 않는다.
4. 현재 브랜치가 `dev`이면:
   - `$ARGUMENTS`(있다면) 또는 대화 맥락에서 지금 시작하려는 작업 내용을 파악해, GitFlow 네이밍(`feat/기능이름`, kebab-case)에 맞는 후보 2~3개를 제시한다.
   - 사용자의 확정을 받기 전에는 브랜치를 만들거나 파일을 수정하지 않는다.
   - 확정받은 뒤에만 `git checkout -b feat/확정된이름`을 실행한다.
5. 마무리로 최종 브랜치명과 워킹트리 상태(깨끗함 / 남은 미커밋 변경사항 요약)를 짧게 보고한다.
